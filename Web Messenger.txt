Web Messenger 🌐
A web version of the Mobile Messenger project.

The situation 👀
To make your mobile messenger even more accessible, you decide to expand its functionality by developing a web version of it.

Functional requirements 📌
You are to create the messenger with Flutter framework. When finished, you should deploy your application to any platform you see fit. It must be accessible from any computer.

Web Messenger and Mobile Messenger share single codebase and database, as Flutter supports multi-platform application development.

Web Messenger should have all the features of its mobile version as well as several additional ones:

UI adaptation
Mobile Messenger UI needs to be adapted for the web adhering to the good practices of web application development.

Group chats
Web Messenger should enable users to create group chats. User must be able to send and receive group invitations. Invitation can be accepted or declined.

Chat search
Web Messenger has to feature a search functionality that allows users to search for specific text within messages in individual and group chats. The search results should highlight matching messages and users must be able to navigate through found messages within the chat.

Error handling
In case of any common errors/failures/interruptions the messenger should give visual feedback about the situation to the user and return to the last stable application state.

Expected outcome 🎯
The finished project should have the following:

Application is a web version of Mobile Messenger with additional features.
Application is deployed on web platform.
Sensitive data is encrypted.
User is able to create or join individual or group chats.
Chats are featuring search functionality.
Extra requirements 📚
Group chat polls
Enable users to create and participate in polls in the group chats. Users can change or retract their vote. Poll creator can set whether the votes are anonymous or public.

Chat screens
Enable users to open at least 2 chats on the same web page.

Bonus functionality 🎁
You're welcome to implement other features as you see fit. But anything you implement should not change the default functional behavior of your project.

You may use any additional tools, command line arguments, or separate builds to switch your bonus functionality on.
